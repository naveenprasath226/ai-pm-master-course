Milestone 01

AI Foundations & Evolution

Foundation

Understand how AI evolved from rules to machine learning, deep learning and generative AI.

The evolution in one picture

Rules → Machine Learning → Deep Learning → Transformers → LLMs → Multimodal AI → Reasoning → Tool use → Agents → Enterprise AI

Core concepts

AIMLDeep LearningNLPGenerative AILLM

What you should know

  • AI: the broad field of machines performing tasks associated with intelligence.
  • ML: systems learn patterns from data rather than every rule being hand-coded.
  • Deep learning: neural networks with many layers that learn useful representations.
  • Generative AI: models that generate text, images, code, audio, video or other content.
  • LLM: a large language model trained to model token sequences and generate language.

PM exercise

Take a business process you know (e.g., invoice approval) and mark every step as rule-based, ML-prediction, generative, or human decision. Explain why.

Checkpoint

Q1. Why did early rule-based AI struggle with messy enterprise processes?
Answer
Because real-world processes contain exceptions, ambiguity and changing conditions. A fixed rule set becomes brittle and expensive to maintain.
Q2. What changed when ML became common?
Answer
The system could learn patterns from historical data instead of requiring every decision rule to be manually specified.
Milestone 02

Machine Learning Without the Math Fear

Core

Understand how models learn, what training data is, and which problems ML is good at.

Key ideas

  • Supervised learning: learn from labelled examples.
  • Unsupervised learning: discover structure without labels.
  • Classification: predict a category.
  • Regression: predict a continuous value.
  • Features: inputs used by the model.
  • Labels: target answers in supervised learning.
  • Training vs inference: learning parameters vs using them to make predictions.

PM exercise

Design an ML project for predicting which implementation projects are at risk of slipping. Define input features, target label, training data, success metric and a human escalation rule.

Checkpoint

Q1. What is overfitting?
Answer
A model learns the training data too specifically and performs poorly on unseen data.
Q2. Why can a highly accurate model still be a bad enterprise product?
Answer
Accuracy may ignore cost of mistakes, bias, latency, explainability, workflow adoption, security and business impact.
Milestone 03

Deep Learning & Neural Networks

Core

Understand the building blocks behind modern neural models.

Conceptual model

A neural network applies learned weights to inputs, passes signals through layers and adjusts those weights during training to reduce error.

  • Neuron / node
  • Weights
  • Activation
  • Layers
  • Loss function
  • Backpropagation
  • Gradient descent

Why scale matters

More data, compute and parameters can improve model capabilities, but the relationship is not magic: data quality, architecture, training methods and post-training matter too.

Checkpoint

Q1. What does backpropagation do?
Answer
It computes how much each parameter contributed to the error so optimization can adjust the parameters.
Q2. As a PM, why do you care about GPUs?
Answer
They accelerate the parallel matrix operations used in training and inference, affecting cost, speed and feasibility.
Milestone 04

Transformers: The Breakthrough

Critical

Master the intuition behind the architecture that powered the modern LLM era.

Attention in one sentence: the model learns how strongly different tokens should relate to one another while processing context.

Know these terms

TokenEmbeddingAttentionSelf-attentionPositional informationTransformer

What happens conceptually?

Text is tokenized → tokens become vectors (embeddings) → transformer layers repeatedly transform those vectors using attention and feed-forward networks → the model predicts likely next tokens or performs another trained objective.

The 2017 paper Attention Is All You Need introduced the Transformer architecture that became foundational for modern language models.

Checkpoint

Q1. Why was the Transformer so important?
Answer
It made sequence processing far more parallelizable and provided a powerful attention mechanism for modeling relationships across context, enabling large-scale training.
Q2. What is an embedding?
Answer
A numeric vector representation that places tokens or other objects in a learned semantic space.
Milestone 05

LLMs: How ChatGPT-Type Systems Work

Critical

Understand the pipeline

  1. Text is split into tokens.
  2. Tokens are mapped to vectors.
  3. The transformer processes the context.
  4. The model predicts a next-token distribution.
  5. Sampling/decoding selects output tokens.
  6. The loop repeats until the response is complete.

Training stages

  • Pretraining: broad language/world-pattern learning.
  • Post-training: instruction following, preference shaping, safety and task behavior.
  • Inference: running the trained model on a new request.

Terms you must be comfortable with

ParametersContext windowInferenceTemperaturePretrainingPost-trainingRLHF

PM exercise

Explain ChatGPT to a CFO in 90 seconds without using the words “magic,” “thinking” or “just predicts text.” Then explain the limits: hallucination, outdated or missing context, ambiguity and non-determinism.

Checkpoint

Q1. Does an LLM have direct access to your live ERP by default?
Answer
No. It only gets information available through the application context, retrieved data, tools or other integrations explicitly provided to it.
Q2. What is the context window?
Answer
The amount of tokenized context a model can consider for a request/interaction, subject to the model’s limits and system design.
Milestone 06

Prompting, Context & Model Selection

Practical

Good prompts are system design

  • State the task and desired outcome.
  • Provide relevant context.
  • Define constraints and boundaries.
  • Give examples when useful.
  • Specify output structure.
  • Ask for uncertainty or missing data to be surfaced.

Model selection

Do not default to the biggest model. Consider quality, latency, cost, context needs, privacy, tool-use capability, reliability and evaluation results.

Hands-on

Create a prompt that converts messy project meeting notes into: decisions, actions, owners, dates, risks, dependencies and open questions. Add a rule that unknown owners/dates must be marked “TBD” rather than guessed.

Checkpoint

Q1. Why is “be smart and summarize this” a weak enterprise prompt?
Answer
The goal, audience, constraints, definition of a useful summary and required structure are underspecified, making quality inconsistent.
Q2. What should a PM measure before adopting a model?
Answer
Task-level quality plus latency, cost, failure modes, security/privacy constraints and the business outcome the model is expected to improve.
Milestone 07

RAG — Connecting AI to Enterprise Knowledge

Critical
RAG = Retrieval-Augmented Generation. Retrieve relevant information first, then give it to the model as context for generation.

Pipeline

Documents/data → chunking/indexing → embeddings → vector/semantic retrieval → optional reranking → relevant context → LLM → grounded answer.

RAG vs fine-tuning

NeedTypical fit
Fresh company policies / docsRAG
Domain-specific behavior/styleFine-tuning may help
Need factual grounding from live dataRAG / tools
Need the model to execute an actionTool calling / agents

Project

Design a procurement-policy assistant. Define document sources, chunking approach, metadata filters, retrieval metric, citation behavior, fallback when no answer is found, and access-control model.

Checkpoint

Q1. Does RAG eliminate hallucinations?
Answer
No. It can reduce unsupported answers by supplying relevant evidence, but retrieval can fail and the model can still misinterpret or invent.
Q2. What is the biggest hidden RAG problem?
Answer
Retrieval quality. If the right information is not retrieved, a powerful model can still produce a wrong answer convincingly.
Milestone 08

Tool Calling, APIs & Function Execution

Practical
A model generating text is different from a model that can use a tool. Tool calling lets the AI request structured actions from the surrounding application.

Basic flow

User → LLM/agent → tool selection → API/function → system result → LLM/agent → user.

Enterprise examples

  • Check invoice status in SAP.
  • Create a Jira ticket.
  • Fetch a customer record.
  • Run a SQL query under controlled permissions.
  • Draft but require human approval before sending an email.

PM exercise

Design five tools for an AI project assistant. For each define: name, inputs, outputs, permission needed, failure mode, retry policy and whether human approval is required.

Checkpoint

Q1. Why shouldn't an agent get unrestricted database access?
Answer
Least privilege limits damage from mistakes, prompt injection, compromised context or unintended actions. Tools should expose only the actions and data the workflow requires.
Q2. What is a tool contract?
Answer
A structured definition of what a tool does, its inputs, outputs, constraints and errors so the model/application can call it consistently.
Milestone 09

MCP — Model Context Protocol

Current

Think of MCP as a standardized interface pattern for exposing tools, resources and context to AI applications. It matters because enterprise agents need repeatable ways to connect to systems rather than every integration being a one-off.

PM-level mental model

AI application ↔ protocol/interface ↔ tools/resources ↔ enterprise systems

Exercise

Sketch an MCP-style architecture for an AI delivery manager that can read project docs, query Jira, access approved customer data and create a risk item—but cannot approve financial transactions.

Questions to ask

  • Who authenticates?
  • What data can the tool see?
  • What actions are allowed?
  • How are audit logs captured?
  • What happens on tool failure?
  • Can one tool call another?

Checkpoint

Q1. Why does MCP matter beyond “another API format”?
Answer
Standardized interfaces can reduce bespoke integration work, clarify tool/resource contracts and make AI applications more interoperable.
Q2. Does MCP itself make a system secure?
Answer
No. Security still depends on identity, authorization, permissions, isolation, validation, auditing and the surrounding implementation.
Milestone 10

AI Agents & Agentic Workflows

Critical
Agentic mental model: observe → plan → act → observe result → decide next step → repeat, with bounded permissions and stopping conditions.

Agent ingredients

  • Model/reasoner
  • Tools
  • State/memory
  • Planning/orchestration
  • Guardrails
  • Evaluation/observability
  • Human approval where needed

Agent design exercise

Design an agent for overdue invoice follow-up. The agent can read invoices, retrieve customer policy, draft an email and open a task. Human approval is required before any external message is sent.

Do not over-agentify

Some workflows are better as deterministic automation. Use an agent when ambiguity, changing context and multi-step decisions create value. Keep deterministic controls around high-risk steps.

Checkpoint

Q1. What makes an agent different from a chatbot?
Answer
An agent can manage multi-step work using state and tools, rather than only generating a conversational response.
Q2. Where should human-in-the-loop be strongest?
Answer
At consequential, irreversible, regulated or high-impact actions where errors are costly and policy requires accountability.

TPM exercise

Create a one-page technical program plan for deploying an AI workflow across an ERP-integrated enterprise customer. Include workstreams, dependencies, environment plan, UAT, security review, rollout and rollback.

Checkpoint

Q1. Why is AI architecture not just “call an LLM API”?
Answer
Production systems need data access, retrieval, tools, identity, security, reliability, evaluation, observability, cost controls and workflow integration.
Q2. What is the PM’s role in architecture?
Answer
You may not own every technical decision, but you must understand dependencies, trade-offs, risks, milestones, acceptance criteria and operational impact well enough to manage the program.
Milestone 12

AI Security, Reliability & Evaluation

Critical

Security risks

  • Prompt injection
  • Sensitive-data leakage
  • Excessive agent permissions
  • Unsafe tool calls
  • Untrusted retrieved content
  • Model/provider dependency

Evaluation

Build task-specific test sets. Track quality by scenario, not by vibes. Measure both model quality and business outcome.

MetricExample
QualityCorrect answer / extraction rate
GroundingEvidence-supported response rate
Agent successTasks completed correctly
OperationalLatency, cost, failure rate
BusinessHours saved, cycle time, error reduction

Evaluation exercise

Create 50 test cases for an AI implementation assistant. Include happy paths, ambiguity, missing data, conflicting documents, malicious instructions and high-risk requests. Define pass/fail criteria before testing.

Checkpoint

Q1. Why is a benchmark score not enough?
Answer
Benchmarks may not represent your customers, workflow, data, policies or failure costs. Production evaluation needs task-specific evidence.
Q2. What does “AI ROI” actually mean?
Answer
Quantified business value attributable to the AI system, net of implementation and operating costs, risk and adoption constraints.
Milestone 13

AI Product & Program Management Mastery

Final

Your AI PM toolkit

  • Problem framing: what outcome are we improving?
  • AI fit: why AI instead of deterministic automation?
  • Data readiness: what context is available and permitted?
  • Model strategy: which model and why?
  • Tool strategy: what can the system read/do?
  • Human control: which decisions require approval?
  • Evaluation: how do we prove it works?
  • Rollout: pilot → controlled expansion → production scale.
  • Change management: how do users trust and adopt it?

Final checkpoint

Q1. When should you NOT use AI?
Answer
When the workflow is deterministic, simple rules solve it cheaply, the data is insufficient, errors are unacceptable without practical controls, or the cost/complexity outweighs the measurable benefit.
Q2. What makes an AI initiative a program rather than a demo?
Answer
Real users, production dependencies, measurable outcomes, security/reliability controls, operating ownership, change management and ongoing evaluation.
